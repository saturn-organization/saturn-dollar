# Saturn Dollar (USDat)

USDat is a compliance-enabled, upgradeable token built on the PYUSDX extension platform. The existing mainnet proxy was migrated from the legacy M-backed `JMIExtension` implementation to a PYUSDX-backed `MultiMint` implementation.

USDat adds the following behavior to `MultiMint`:

- optional whitelist checks on wrap and unwrap operations;
- account freezing, pausing, and forced transfers for compliance operations;
- compatibility with the legacy proxy's storage namespaces;
- progressive replacement of legacy M reserves with PYUSDX; and
- permissionless realization of M yield to the configured yield recipient.

The project uses [Foundry](https://book.getfoundry.sh/) and Solidity `0.8.34`.

## Architecture

USDat runs behind the existing transparent upgradeable proxy. The proxy holds balances, roles, and accounting state; the implementation supplies logic.

| Component | Responsibility |
|---|---|
| USDat proxy | User-facing token address and persistent storage |
| `src/USDat.sol` | Upgrade-only implementation built on `MultiMint` and `ForcedTransferable` |
| ProxyAdmin | Performs implementation upgrades; owned by `SaturnTimelock` |
| `SaturnTimelock` | Schedules upgrades with a 5-day delay |
| Asset-cap timelock | Manages the `replaceAsset` caller whitelist and M asset cap |
| PYUSDX SwapFacility | Wraps, unwraps, and replaces backing assets for approved extensions |

```text
USDat
├── MultiMint
│   ├── PYUSDX wrap and unwrap
│   ├── alternative-asset accounting
│   └── replaceAsset
├── ForcedTransferable
├── compliance whitelist
└── legacy storage-slot adapters
```

The implementation constructor pins PYUSDX and its SwapFacility as immutables. It has no production `initialize` function because it is only intended to replace the implementation behind the already-initialized USDat proxy.

### Migration behavior

The upgrade atomically calls the one-shot `migrate()` reinitializer:

1. Read the M held by the proxy.
2. Require that it covers the legacy M-backed portion of supply.
3. Mint any M surplus to `yieldRecipient()`.
4. Register the complete M balance as a 6-decimal `MultiMint` alternative asset.

M remains earning while the reserve is progressively replaced with PYUSDX. `claimMYield()` registers newly accrued M as backing and mints the corresponding USDat to the yield recipient. It is permissionless because the caller cannot choose the recipient.

See [the migration runbook](plans/usdat-pyusdx-migration-runbook.md) for the exact upgrade and wind-down sequence.

## Development

Initialize dependencies after cloning:

```bash
git submodule update --init --recursive
```

Run the local checks:

```bash
forge fmt --check
forge build src/USDat.sol --sizes
forge test --no-match-contract UpgradeUSDatForkTest
```

The build command is scoped to the production contract so the EIP-170 size check does not include `USDatHarness`, whose test-only initializer and mint helper make it intentionally non-deployable. Running `forge build --sizes` without a path checks every test and script contract as well and therefore reports the harness as oversized.

The mainnet-fork suite requires an RPC endpoint:

```bash
MAINNET_RPC_URL=<rpc-url> \
  forge test --match-contract UpgradeUSDatForkTest -vvv
```

Build settings are defined in `foundry.toml`: Solidity `0.8.34`, Cancun EVM, optimizer enabled with 200 runs, and `via_ir = true`.

## Upgrade operations

Copy `.env.example` to `.env` and provide the required credentials. The current Make targets are:

```bash
make deploy-upgrade-impl       # future implementation deployments
make propose-upgrade-calldata # print schedule calldata for Fireblocks
make propose-upgrade          # submit schedule through Fireblocks
make execute-upgrade          # execute after the timelock delay
```

For a new implementation, deploy first and update `UpgradeUSDatBase.NEW_IMPLEMENTATION` before proposing. The propose and execute scripts rebuild the same `ProxyAdmin.upgradeAndCall(proxy, implementation, migrate())` payload, so a mismatched implementation produces a different timelock operation ID and cannot execute the scheduled operation.

`script/VerifyCodeHash.s.sol` can deploy the implementation locally with the production constructor arguments and print its runtime code hash:

```bash
forge script script/VerifyCodeHash.s.sol:VerifyCodeHash
```
